# AShareLens 平台设计

**日期：** 2026-07-29  
**状态：** 已批准  
**许可证：** MIT  
**产品名称：** AShareLens（A股透镜）  
**定位：** 开箱即用、可解释、可复现的本地 A 股量化选股平台。

## 1. 目标与边界

AShareLens 面向个人投资者、Python 策略开发者和量化研究者，覆盖沪深京 A 股的日线收盘选股、历史回测、每日模拟组合、Web 管理、定时运行和结果推送。

首个稳定版本必须支持：

- BaoStock 默认免注册真实数据，AkShare 补充与校验，Tushare 可选配置。
- Pydantic 参数模型驱动的 Python 策略插件与 Web 表单。
- 四个内置策略：均线趋势、横截面动量/RPS、价值质量多因子、上升趋势回调。
- A 股 D 日收盘生成信号、D+1 日开盘模拟成交。
- 回测和每日模拟共用同一事件内核。
- 解释型信号、运行指纹、数据质量门禁和全程数据血缘。
- MySQL 8.4 LTS、Docker Compose 三服务部署、消息推送。
- 中文主文档、英文摘要文档、MIT 开源发布。

首个稳定版本明确不包含实盘交易、分钟级行情、机器学习训练平台、多租户和分布式计算集群。

## 2. 架构

项目使用单仓库、单 PyPI 包、逻辑分层的模块化单体：

- `asharelens.core`：纯 Python 领域内核，不依赖 Web、MySQL 或消息系统。
- `asharelens.data`：统一数据模型、数据源插件、版本和质量门禁。
- `asharelens.server`：FastAPI、认证、配置、REST API 和 Web 静态资源。
- `asharelens.runner`：调度、持久任务队列、数据同步、策略和回测执行。
- `web`：Vue 3 + TypeScript 前端。

Docker 产品只包含 `app`、`runner`、`mysql` 三个服务。`app` 和 `runner` 使用同一镜像的不同启动命令。Python SDK 通过 `pip install asharelens` 安装，服务端依赖通过可选 extra 安装。

核心依赖方向必须满足：

```text
server ─┐
runner ─┼──> core
cli ────┘

core 不得反向依赖 server、runner、ORM 或具体数据源
```

## 3. 插件模型

平台定义四类稳定插件协议：

- `StrategyPlugin`
- `DataProviderPlugin`
- `FactorPlugin`
- `NotifierPlugin`

插件必须声明 API 版本、插件版本、能力清单和兼容范围。个人用户可以挂载单文件策略；正式插件使用 Python Entry Points 发布。

策略通过 Pydantic 模型声明参数。服务端读取 JSON Schema 后自动生成 Web 表单。策略只接收不可变的 `StrategyContext`，不能直接访问数据库、文件系统或网络。策略返回结构化的 `SelectionCandidate`，至少包含证券、信号日期、是否入选、得分、排名、原因、指标快照和数据警告。

插件在子进程中运行，并配置超时、内存限制、日志捕获和异常隔离。该隔离用于保护可用性，不把不可信 Python 代码视为安全代码；首个稳定版本只运行用户信任的插件。

## 4. 数据设计

BaoStock 是默认真实数据源；AkShare 用于补充、备用和抽样校验；Tushare 是用户配置 Token 后启用的增强源。CI 和离线体验使用确定性合成数据。

数据按“数据集 + 交易日”形成分区。单个分区只能有一个生效来源，禁止行级静默混源。每个生效分区记录：

- 提供方和接口版本
- 拉取批次
- 原始内容哈希
- 标准化版本
- 数据质量结果
- 生效时间

MySQL 保存业务和当前规范化数据。不可变原始批次与可复现快照可以使用应用持久化卷中的 Parquet 文件，无需增加服务。

质量门禁检查日期新鲜度、覆盖率、重复记录、OHLC 合法性、成交量、停牌、复权连续性、财务发布日期、股票池时间有效性和跨源偏差。失败级问题阻止运行；警告级问题允许降级运行并在结果中显著展示。

## 5. 选股、组合与交易

策略输出候选、分数和解释；组合引擎输出目标权重；交易引擎比较目标权重和当前持仓后生成订单。默认组合为 Top 10 等权、单股不超过 10%、每日选股、每周调仓。

交易日 D 的统一事件顺序：

1. 应用 D 日开盘前生效的公司行动。
2. 执行上一交易日生成且计划在 D 日开盘成交的订单。
3. 以 D 日收盘价计算持仓市值和净值。
4. 对截至 D 日的数据执行质量门禁。
5. 计算因子并生成 D 日收盘信号。
6. 构建目标组合和 D+1 日订单。
7. 保存解释、数据版本和运行指纹。
8. 推送选股结果和待执行订单。

买入价使用 `D+1 开盘价 × (1 + 买入滑点)`，卖出价使用 `D+1 开盘价 × (1 - 卖出滑点)`，随后按不利方向进行报价单位取整并限制在当日高低价和有效涨跌停价格内。

交易模型必须支持：

- T+1 可卖数量。
- 主板、创业板、科创板、北交所、ST 和新股的按日期版本化规则。
- 最小交易单位、佣金最低收费、印花税和过户费。
- 停牌、开盘涨停买不到、开盘跌停卖不出的拒单。
- 默认三交易日订单有效期和新目标组合对旧订单的替代。
- 使用截至 D 日的平均成交额估算容量，禁止使用 D+1 全日成交量决定开盘成交。

## 6. 可解释、可复现和可追溯

每次运行产生规范化指纹：

```text
SHA256(
  策略代码哈希
  + 规范化参数 JSON
  + 数据快照清单
  + 股票池版本
  + 组合规则版本
  + 交易和费用规则版本
  + 引擎版本
  + 依赖锁哈希
)
```

用户可以从选股理由追踪到因子值、规范化记录、数据分区、拉取批次和提供方。相同运行指纹必须产生相同结果，并由金标测试持续验证。

## 7. Runner

首发使用 MySQL 持久任务队列，不引入 Redis 和 Celery。Runner 包含 Scheduler、JobRepository、Dispatcher、ExecutorRegistry、Heartbeat、Reaper 和 WorkflowCoordinator。

Runner 使用 `SELECT ... FOR UPDATE SKIP LOCKED` 领取任务，以 Lease 和 Heartbeat 识别失联任务。任务采用至少一次交付；数据批次、运行指纹、成交、组合日期和通知通过唯一幂等键保证业务效果只发生一次。

`TaskBroker` 是稳定抽象。只有在多机 Runner、分钟级任务、大规模并行回测或 MySQL 队列成为实际瓶颈时，才增加 Redis/Celery 适配器。

## 8. Web、部署和安全

Web 提供首次向导、系统首页、数据中心、策略、每日选股、解释、回测、模拟组合、订单成交、定时任务、推送和设置页面。默认界面面向非技术用户，高级参数折叠展示。

用户通过三步启动：

```text
下载项目
docker compose up -d
访问 http://localhost:8000
```

默认只绑定 `127.0.0.1`，MySQL 不暴露宿主机端口。首次启动生成主密钥并保存在持久化卷中，外部数据源凭据加密保存。项目不默认收集遥测。

升级通过拉取固定版本镜像完成。数据库迁移前自动备份，迁移失败时阻止新版本启动。镜像提供明确版本、`stable` 和 `preview`，不发布含义不明确的 `latest`。

## 9. 测试和发布门槛

测试体系覆盖单元、属性、数据源契约、MySQL 集成、金标回测、Web 端到端和 Docker 干净环境启动。必须专门测试防未来函数、T+1、停牌、涨跌停、费用、公司行动、现金和持仓不变量，以及回测与每日模拟的等价性。

公开 `v0.1.0-alpha` 前，必须在干净环境完成：

```text
启动 → 免费数据同步 → 参数化选股 → 解释
→ 回测 → 模拟组合 → 定时运行 → 消息推送
```

仓库使用中文 README、英文摘要、MIT、贡献指南、行为准则、安全策略、Issue 表单、PR 模板、路线图和完整截图。真实行情数据不随仓库或镜像分发。
